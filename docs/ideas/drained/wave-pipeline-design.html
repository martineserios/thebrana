The Wave Pipeline

thebrana · backlog-drain epic · 2026-08-14 · design corpus, both authors

How thebrana builds itself: work flows through durable queues, loops pump it forward, and every irreversible step passes a human valve — and the human works in two rooms: the studio, where direction is created in dialogue, and the cockpit, where decisions take seconds. Only the innermost loop is the /loop command — the outer ones are achieved by harness design, and the outermost has no command at all: it is knowledge being processed and reused.

Inside the loops library

The catalog's core claim: a loop is a declared artifact, not an improvised prompt. Every entry states what it drains, what it fills, how it paces, and which verbs it is denied — reviewable before it ever runs, exactly like a skill.

What a loop entry declares

Frontmatter schema, from loops-library.md — the input types of a loop definition
name · cadence · pacingPacing is time (fixed beats) | work (drain while work exists) | event (a Monitor fires). Lived finding from tonight's 8 beats: work-pacing wants three delays, not one — {active: ~90s, waiting: 20min+, empty: 30min+}, and the pull outcome tells the loop which state it's in (Pulled / AtLimit / NoneEligible map 1:1).
autonomyL0 report → L1 prepare → L2 merge-the-trivially-safe → L3, plus a supervised flag. Unattended is hard-gated on the ADR-062 sandbox regardless of level.
drains: · fills:Queue references — the loop's entire relationship to the rest of the system. Loops compose only through these (law 1); a loop that fills what another drains is a pipeline, with backpressure for free.
spawns:Which runners a beat may launch, with a max concurrency — the recursion bound that keeps a foreman from forking a fleet.
records:The per-beat record schema — always emitted, verbosity is a render toggle. Records are what the watchdog reads, what the TUI renders (bounded queue → progress bar, unbounded → heartbeat), and where lease claims live.
BodyBeat procedure + cheap preflight (no-op fast) + stop conditions (real signals only) + denied verbs — the valves, written into the definition itself.

The five-verb pull interface

Every queue answers these, however it's stored — the abstraction lives here, never in a mirror store
peekWhat's eligible, without taking it. Waves: resolve selector. inbox/: oldest file. Refs: list ready/*.
pull the hard oneTake exactly one item, atomically — each store uses its native primitive: waves = flock sidecar + fresh-read + status write (proven: 20 concurrent processes, zero double-pulls); inbox/ = mv to .processing/ (rename is the lock); git = update-ref; jsonl = flock + rewrite; external APIs = conditional update, the one race-prone store. Eligibility is enforced inside pull, queue-side — no pump can bypass the valve.
ackTwo grades: mechanical (URL digested — self-ack) vs judged (a wave task — acked only through build CLOSE with evidence; "completion is graded, not asserted"). Each queue's spec declares which grade it requires.
dead-letterThe explicit "no", with a reason: park + note (waves), .dead/ + sidecar (inbox), rejected/* (refs). Feeds the standing triage wave.
depthHow much is waiting — the number backpressure and the wave board both read. Anything that answers depth is renderable and watchable for free.
Leases gapThe verb that's missing everywhere: pull should take a lease (claimant + expiry in the beat record) so a pump that dies between pull and ack doesn't strand its item — today a dead drain session leaves its task in_progress forever. Stale-lease requeue becomes the watchdog's second job.

The design, primitive by primitive

Four primitives are the whole vocabulary. Everything the system is or will become — standing waves, shadow drains, dead-letter triage, graduated autonomy — is not an extension bolted on; it is one of these four, arranged. Each family below carries its full range: what runs today, what the design already contains, and where the known holes are.

Queue — durable state holding work between pumps

Contract: item · pending→pulled→done|dead · eligibility valve · atomic pull · dead-letter path · WIP bound
Waves liveNamed, gated, drainable selectors over tasks — the queue this page proved. wip_limit is the pipe width; gate chains waves into graphs (sequential = chain, parallel = siblings).
Waves from structure designedSelector form parent:ms-52 — the plan's milestone tree is the wave graph, no tagging step at all. Planning emits queues as a side effect of planning.
Standing waves designedAlways-draining intake (kind:fix ∧ approved): bugs get approved and simply get worked, forever. A queue with no end state.
Dead-letter wave designedTwice-failed tasks auto-park into a standing triage wave with its own closer pump. The explicit "no" path every stage owes its work — queueless rejects rot (the 160-day-stale root cause).
Other materializations designedSame contract, different stores (loops library): inbox/ dirs (rename = atomic pull), URL jsonl, git ready/* refs (update-ref = atomic pull), external APIs. Native stores stay authoritative — the abstraction is only the five verbs.

Pump — a loop moving work exactly one stage forward

Some pumps are the /loop command; some are the harness's own design. All obey the beat anatomy of Fig 4.
Drain pump livewave pull each beat — atomic, concurrency-proven (20 processes, wip_limit 5, exactly 5 pulls). Ran 8 supervised beats to build t-2813, its own permanent form. Runbook: drain-loop.md.
Epic runner designedWalks the wave graph instead of one wave: drain the first gate-satisfied wave, pull to contract, surface the ship decision, let shipped unlock the next. The t-2828 centerpiece.
Shadow mode designedReport-only beats: the pump says what it would pull, zero writes. Review the simulation, then arm — trust granted on proof, for every new pump and wave graph.
Leases gapA pump that crashes between pull and ack strands its task in_progress forever — true of today's shipped pull. Fix: pull takes a claimant + expiry; stale leases get requeued by the watchdog. The loops library's sharpest find.

Valve — a human gate between stages

Never automated, and never armed by the party it constrains. Autonomy grows by moving valves, not by smarter pumps.
ac approve liveThe trust boundary between selector-match and autonomous execution — promote + flip, verb-only, denied to every runner. First real use opened tonight's drain.
Merge & ship liveExecutors return branches; you integrate. Shipped on a wave is a double act: sign-off on wave N and the key to wave N+1's gate.
Wave-level approval designedReview a wave's proposed criteria as one batch, approve in one action — one decision per wave, not per task. The valve gets coarser as trust grows.
Graduated autonomy designedA wave class with 5 consecutive approved-unchanged cycles is promoted by rule (e.g. docs-only waves earn auto-merge). Narrow pipes earn trust independently; promotion is evidence, never assumption.

Gauge — a readout on a queue or on the pumps themselves

Gauges never act — they make the human's next decision cheap.
Wave board designedbrana backlog wave board: gate chains drawn as a graph, matched / approved / in-flight / done per wave. The morning cockpit.
Watchdog designedOne external meta-gauge over every loop's last-beat records — outside the loops it guards. Session death is loop death; only the watchdog notices. Second job once leases exist: requeue the stale ones.
Contract-met designedMachine-checkable contract ("all matched completed ∧ validate.sh green") announced the moment it's true. You still ship; you stop polling. Precondition for ever letting a gate auto-advance.
Beat telemetry designedEvery drain records beats, pulls, failures, cost — the usage data the deferred wip_limit default was waiting for. The system measures itself into its own tuning numbers.

The two rooms — where you create, where you operate

You appear in this system in two entirely different postures, and the whole architecture exists to keep them distinct: loops protect the first and speed the second.

What each room gets from the system

Loops cannot create and must not interrupt — they serve the studio and staff the cockpit
Studio inputsGauges feed the conversation (wave board, health digests, telemetry — the facts on the table when you bring a topic); memory feeds it depth (what we decided before, what failed, why). The studio's output — epics, wave graphs, approved contracts — is what fills every queue the pumps drain.
Cockpit inputsThe needs-you digest and the wave board surface exactly the valve decisions waiting: approve this wave's AC, merge this branch, ship this wave, triage this dead-letter. Each arrives with its evidence attached (the graded ack), so a decision costs seconds, not investigation.
The line betweenA valve-feeder that can't classify an item confidently routes it to the studio agenda, never the interrupt stream — under-escalating a design question into a rubber-stamp is the worse failure. The agenda itself is a queue: depth tells you how much thinking is waiting for your next session.

Where this goes

/brana:backlog plan "epic"  →  review + approve the waves it proposes  →  /loop drain epic

Planning emits the wave graph. You sign once per wave, not once per task. The loop walks the graph: drains the first gate-satisfied wave, pulls until its contract is met, surfaces the ship decision, and your shipped unlocks the next wave. Your job becomes pipeline design; the loops do the pumping. — t-2828, where this page's design and the loops library converge

The seven operating laws

Loops never talk to each other — queues do.Coordination is backpressure: a full downstream queue makes upstream pumps no-op. If two loops need to message each other, the design is wrong — add a queue. The foreman fills a queue; it never calls workers.
Every loop needs a dead-letter path.Failed beats and poison tasks go to an explicit "no" queue with its own closer pump. Rejected work without a queue becomes invisible and rots — the documented root cause of the 160-day stale tasks.
One external watchdog watches all loops.It reads last-beat timestamps from durable records and sits outside the loops it guards. Session death is loop death — only the watchdog notices.
Beats are idempotent.No catch-up on missed fires and crash re-runs mean a beat replayed twice must be safe. The atomic wave pull is the reference implementation.
Cost per beat ≈ context size.Loops live in lean dedicated sessions; cheap preflight always fires first. A loop whose beats cost more than the work they move is a net negative — beat telemetry measures exactly that.
Loops are testable.Rehearse beats against a fixture queue before arming for real. Shadow drains are the wave-native form of the same discipline.
Lifecycle is unfinished business.Hard 7-day expiry, Esc kills a waiting loop, no pause/resume. The loop library needs a stance on retirement and re-arming — not just birth.

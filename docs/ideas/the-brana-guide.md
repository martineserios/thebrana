# The Brana — studio guide (top-down, living draft of `docs/architecture/the-brana.md`)

> How to use: we descend one level at a time. Each node has **IS** (one line) · **PERSPECTIVES** (optional — see ladder below) · **SEAM** (optional — flagged, not resolved, when the metaphor strains) · **DECIDED** ✅ · **OPEN** ▢ (we discuss and define) · **DOCS** (owner first, then supporting). Every ✅/▢ line carries `[refs]` — the docs/ADRs/ideas/specs/memory it touches, so any later refactor can trace it. Marks: ✅ decided · ▢ open · ⏸ parked (later, on evidence). Full reference index in **Appendix A** (every doc in the cluster: role · status · action · chapter). Paths relative to `thebrana/` unless prefixed; `WT:` = exists only in a worktree.
>
> **Complexity ladder (2026-08-19):** for a node with real content to explain (not just a scoping call), build it through four rungs — **Plain** (no jargon, explain to a smart friend outside tech) → **Practitioner** (brana's own vocabulary: task/branch/worktree/skill, no physics) → **Structural** (the formal shape: how the pieces relate) → **Precise** (the full brane-physics mapping). One rung per exchange, not one node per exchange — check each rung before drafting the next. A node is only ✅ when the rungs agree with each other; if a precise-rung claim can't be traced back down to the plain rung, the mapping is forced somewhere. When forcing is the honest call anyway (practical > pure), keep it — but record the strain as a **SEAM** instead of smoothing it away.

## L1 · Three chapters + the Scale axis

```
             SPACE (what things are)   CYCLE (what it does)      GATE (who decides)
knowledge    bulk / portfolio          LEARN loop, slowest        studio — you live here
epic         project brane             epic-drain                 wave ship valve
beat         station                   drain beat                 merge valve, cockpit
micro        grain                     TDD red-green              a test — no human
                                 ← SCALE axis: ring = dimension = frequency →
```

**IS.** Space = units and boundaries · Cycle = motion (loops carrying work through queues, returning) · Gate = human decisions and their placement · Scale = the same skeleton at every ring, warped; each ring a whole system with its own memory and judge.

**PERSPECTIVES** (complexity ladder — plain → practitioner → structural → precise; built one rung per exchange, 2026-08-19)
1. **Plain.** Any piece of work — from fixing a typo to running a whole business — has three questions underneath it: what is this thing made of (its parts, its boundaries)? What is it doing right now (the motion)? Who says it's actually done (someone has to decide, or nothing finishes)? Same three questions at every size.
2. **Practitioner.** Space = what's sitting in the repo: projects, the stations (skills/workflows) inside them, the grains (files/functions) inside those, plus the global rules in `~/.claude/` every project obeys. Cycle = what's running: a `/loop` pulling a task through TDD red-green, a wave draining the backlog, an epic worked over days — same do-it/check-it/come-back motion at different sizes. Gate = the actual moments a human says yes (AC approval, merge, ship) vs. the moments a test just decides on its own because nothing bad happens if it's wrong. Scale = the same three questions apply from one red-green cycle (seconds) to the whole knowledge loop (weeks) — same shape, different speed.
3. **Structural.** The three chapters are not a sequence — they're three simultaneous facets of the same unit: at any moment, any unit at any ring *is* something, *does* something, and is *decided on* by something, all at once. Scale is the orthogonal axis: the same three-facet structure repeats, self-similar, at four nested rings (micro→beat→epic→knowledge) — 4 rings × 3 chapters = the table's 12 cells above. Inside every Cycle cell, the motion has the same internal shape regardless of ring: the seven-step skeleton (ORIENT→SELECT→ACT→MEASURE→JUDGE→ASSIMILATE→RESTART) — context/action/feedback is this skeleton's plain-language compression (ORIENT+SELECT=context, ACT=action, MEASURE+JUDGE+ASSIMILATE=feedback), not a rename of the three chapters. The human is a low-pass filter across the stack: fast rings run unseen, slow rings need them constantly.
4. **Precise.** Space/Cycle/Gate = three physically separate questions about a brane: which fields are localized on it (Space), how strings propagate on/through it (Cycle), what boundary conditions are imposed at its edges (Gate — a Dirichlet condition pinning an open string's endpoint IS a decision point). Scale = compactification radius; small radius→high KK frequency→fast; large radius→low frequency→slow — Randall-Sundrum warping (same physics at every point, exponentially rescaled), not arbitrary self-similarity. The skeleton = a string's worldsheet trajectory: ORIENT/SELECT = sampling background fields present on the brane; ACT = propagation/interaction; MEASURE/JUDGE/ASSIMILATE = coupling back to observable fields, renormalizing; RESTART = closed-string periodicity (σ+2π=σ) — a genuinely tight fit. Human-as-low-pass-filter = effective field theory: an observer at low energy doesn't see high-frequency modes directly, they're integrated out into effective low-energy parameters, though they still do real work underneath.

**SEAM** (flagged, not resolved — practical call, kept on record): Gate-as-boundary-condition is solid for *why* an open string (a workflow) stays pinned, but the physics has no derivation for *why a human specifically* sits at Gate rather than some other selection rule — "irreversible decisions need a human" is a value brana imports, not something brane physics hands us. Kept anyway: physics carries the mechanism, humans carry the values. Watch for this same seam recurring at L4 (Gate chapter proper) — if it does, it's the pattern, not a one-off.

## Context

t-2490 proposed making skills **atomic** — one job, typed input/output — and composing them into procedures via loops and graphs, so one unit is reusable across graphs ("design for graph engineering"). It was gated on t-2488 and explicitly forbidden from papering over t-2278's evidence-based de-risking: t-2278's real audit of 34 first-party skills right-sized skills-as-loops to a focused L refactor (22 skills untouched; the pipeline/assembly-line model deferred as a north-star that must be *earned* by evidence that single-station loops hand off cleanly).

Between t-2490's filing (2026-07-27) and this decision, the ground moved:

1. **The outer graph layer shipped without touching skill internals.** Waves + `gate:` (ADR-080) are a graph as data; `system/loops/` (loops-library, 2026-08-17) is a typed, committed loop catalog (`autonomy`, `drains:`/`fills:`/`spawns:`, `records:`); `epic-drain` topo-sorts and walks the wave graph, invoking `/brana:build` **whole** as a station. Stations — each loading its skill whole — became graph nodes with zero decomposition.
2. **A code-graph runtime already exists**: the `Workflow` tool (`agent()` nodes, `pipeline()`/`parallel()` edges, `schema` for typed returns) with three committed graphs (`sweep.js`, `verify-findings.js`, `hive-mind.js`) — used only for judgment fan-out, never for the main procedure.
3. **An untyped primitive layer is already in production**: `system/skills/_shared/*.md` (epic-ancestor-walk, branch-prefix, guided-execution, adversarial-hive-mind, smart-router…) and `system/agents/`.
4. **Pocock's two-tier pattern is entering brana via ADR-084** (thin user-invoked wrapper → model-invoked primitive; pilot t-2834 vendors `diagnosing-bugs` inside `/brana:fix`'s shell). Read structurally, his repo's stance is: *a skill is a node, never the graph; the graph lives in tracker data and router prose; the loop is the walker (a human or `claude --bg`), not a skill; in-skill fan-out only for verdicts.* Brana converged on the same architecture independently — and added the loop runtime and code graphs Pocock lacks.

The one precise gap the brainstorm surfaced: two disjoint invocation surfaces — **human-supervised, one-at-a-time** (skills, `AskUserQuestion`-native, callable whole as a loop station) and **headless fan-out** (Workflow `agent()`, no human) — with no shared unit that runs both ways. `/brana:build` can be a whole station for a supervised loop but cannot be a `Workflow` node. This is not a missing contract; it is a monolith *by design* — the phase files internalize the graph precisely to carry enforcement (spec-gate, checkpoints, evaluator, docs-before-close), which Pocock has none of.

**The gap is causing pain today** (duplicated-logic test, thebrana-50 synthesis session, 2026-08-18 — three pairs, all *drifted* duplication): (A) `verify-gates.md:101-102` ↔ `system/agents/build-evaluator.md:55-67` restate the MET/PARTIAL/MISSED rubric; `verify-gates.md:120-154` ↔ `_shared/challenger-gate.md:187-229` restate the repair loop near-verbatim; and a live **contradiction** — challenger `CALIBRATION.md:25-28` ("SPLIT never counted FALSE_POSITIVE") vs `verify-findings.js:27-28,110` ("ties drop to FALSE_POSITIVE"), plus the JS emitting `UNVERIFIED` (`:111`) absent from its own enum (`:66`). *[Freshness note 2026-08-23, pre-mortem F1: the js half has since been partially hardened — voters now default to 3 (odd, ties impossible) and `UNVERIFIED` is a deliberate documented state (t-2149). The grain duplication in pairs A/B is re-verified still live; the contradiction half is smaller than stated here.]* (B) `_shared/adversarial-hive-mind.md` ↔ `hive-mind.js`: lens sets share only "systems"; the ≥2-worker corroboration rule is prose-only; the md routes through `verify-findings.js`, the js forbids it. (C) `build-loop.md` ↔ `_shared/delegation-tdd-checklist.md`: delegated agents get a materially weaker TDD contract (no red-commit / `tests_required`, no TEST→IMPLEMENT gate); **no headless TDD prompt exists anywhere** in workflows or loops — runners inherit TDD only by invoking the skill whole. The observed fix direction is not a typed schema: it is **single-sourcing each grain as a file both paths `Read`** — `agent()` nodes can Read files; Workflow JS itself cannot import (`verify-findings.js:82`).

## Decision

**D1 — Verdict on t-2278: leave as planned.** Its de-risked scope (routing heuristic + ADR, ~2 standalone loops, ~2 workflows formalized, ~4 loop-bodies wired to drain waves, 2 retires, 22 skills untouched) stands unchanged. Its blocker (backlog-v3 schema / waves) has landed; it is unblocked, not reopened. The pipeline north-star stays deferred; nothing here earns it.

**D2 — No new station or grain schema.** Brana does not introduce a typed station manifest, a new primitive type, or a per-phase I/O schema. Composition uses what exists: stations (skills loaded whole as nodes), waves + `blocked_by` (graph as data), `Workflow` scripts (graph as code), `system/loops/` (loops), `_shared/` blocks + agents (grains), router docs (prose routing — `idea-to-ship.md`, `delegation-routing.md` stay prose; a router need not be code). **Graph is the parent shape; `Workflow` (code, runs once) and data walked by `/loop` are its two realizations**, chosen by the settled rule — *runs once → Workflow script; humans between nodes → data + `/loop`* ([the-brana.md §Cycle → Decided](../the-brana.md); no Pocock analogue). The seven operating laws (the-brana.md §Cycle → Mechanics) bind every composition: D4's "every hop is a context re-entry" is law 5 applied, D5's raise-into-store is law 1 applied. Hooks' placement (deterministic edges vs Gate) is **OPEN** in the guide (L3, leans Gate) and is not decided here.

**D3 — The station contract is Pocock's two-tier, applied to new and adapted skills.** A station is a *model-invoked* skill (the grains it `Read`s are `_shared/` blocks or agent-owned files) with (a) one job, (b) **asks that are named, carry a `suggested_default`, and assume no human mode — the caller compiles them** (L4.2 `ask()`, D5; asking is caller-compiled behaviour, never an intrinsic property of the unit), (c) a schema'd return when called as a Workflow node. Wrappers are thin, user-invoked, and own orchestration + gates. Mechanism, split by property: (a)/(c) via ADR-084's DEPEND wrappers (pending t-2837) and the Workflow `schema` option; invocation *reach* (model- vs user-invoked) via t-2832's `disable-model-invocation` taxonomy. (b)'s mechanism is L4.2 itself; `disable-model-invocation` does not touch it (the invocation axis is orthogonal to human mode — guide L2 ✅; t-2832's own scope guard; ADR-076 documents the field as a friction nudge). What has **no check today is conformance**: asks with no `suggested_default`, or asks that hard-block a headless caller. The baseline — 26 of 33 model-invoked skills mention `AskUserQuestion` ([skill-tier mapping](../../research/2026-08-23-skill-tier-mapping.md)) — is a count, not a defect. The conformance check is **t-3041**, advisory first. No existing monolith is rewritten to satisfy this; it governs what is added or adapted.

**D4 — Granularity floor.** A phase file becomes a separately-invocable station **only when it has ≥2 callers or must run headless.** Otherwise it stays a phase file inside its skill. Applied to `/brana:build` this yields **one extraction and one wiring** (guide L2 ✅), not nine stations — each with its skeleton-step × ring coordinate: the **TDD loop body** (**ACT @ micro**) (the red→green→refactor core of `build-loop.md`, not the whole phase file — its two gates, the challenger RECONSIDER block at `build-loop.md:89` and the no-tests TDD gate at `:117`, stay wrapper-side; needed by build and fix, must run under a runner — and today has no headless counterpart, pair C above) and the **judgment grains** (**JUDGE @ beat** — the verify-gates fan-out's verdict rubric, repair loop, corroboration rule) that pairs A/B show restated across `verify-gates.md`, `_shared/challenger-gate.md`, `_shared/adversarial-hive-mind.md`, `system/agents/build-evaluator.md`, `hive-mind.js`, `verify-findings.js` — **single-source each as one file that both the skill phase and the `agent()` prompt `Read`**, then delete the restatements. That is the mechanism of "wiring": a shared grain file, not a schema. Homes follow the three-homes rule ([the-brana.md §Space → Grain files](../the-brana.md)): the verdict rubric → `system/agents/build-evaluator/rubric.md` (one agent's own judgment); repair loop and corroboration rule stay in `_shared/` (multi-station). CLASSIFY/SPECIFY/DECOMPOSE (human judgment) and the gates (enforcement) stay in the wrapper. **"Caller" means an actual `Read`/invocation site** in a skill phase, agent prompt, loop, or Workflow script — doc cross-references don't count. A station that drops below the floor is merged back into its remaining caller (demotion rule). The floor governs extractions going forward; the pre-existing `_shared/` layer is precedent, not audited against it (`smart-router.md` has one caller today and stays as-is).

**D5 — The dual-mode gap resolves at the runner layer, not the skill layer.** Headless nodes are agents/Workflow prompts (verdicts, mechanical work); supervised stations are skills. Where one station must run both ways, the runner (`claude -p` per worktree, ADR-060) runs the *skill* with each `AskUserQuestion` compiled per the caller's human mode — the L4.2 `ask()` table ([the-brana.md §Gate](../the-brana.md)): `inside` → ask; `valve` → raise a hand into the pending-questions store (ADR-063) and stop the beat; `none` → take the station's suggested default **only if the caller's grant covers it**, else degrade to `valve`. Nothing is auto-answered (ADR-063: answering is a human-only gate). **The `valve` path is unbuilt** — today the only headless escalation is `autonomous-runner.sh` `plan_task`'s up-front NEEDSHUMAN; mid-task raise is t-3021, blocked_by t-2834. Until it lands, D5 is a placement decision (resolution belongs at the runner layer), not a shipped capability — **logged as an assumption**, per L4.2; the `ask()` prose's owner is `system/loops/README.md §ask` ([the-brana.md §Gate](../the-brana.md)), not this ADR. **Human mode (`inside | valve | none`; the guide's "presence" interlock is the same axis) is set by the caller, never by the station**; a station may only *suggest* a default per named ask (operator decision, thebrana-50 synthesis session, 2026-08-18 — a typed reading of ADR-063, not a skill-schema change). No dual-mode unit abstraction is built.

**D6 — Evidence before generalization.** t-2834 (vendor `diagnosing-bugs` into `/brana:fix`) is the evidence beat: brana's station contract is *read off its adapter* (inputs mapped, output homes, denied verbs), not designed abstractly. A second bounded pilot (vendor `tdd` per ADR-084 — pending t-2837 — with `build-loop.md` calling it) follows only if t-2834's seam holds. The station-admission checklist (guide L2.2a ✅: queue · stop_condition · dead-letter · **denied verbs** · rooms · packet in/out; L2.2b ▢ OPEN, blocked_by t-2834: judge policy · assimilate · restart) is applied to *bindings that become stations*, starting with t-2834 — never as a gate on all ~40 skills. A manifest file is written only if a third binding shows the same fields repeating (the "generalize after 2–3 bindings" rule three prior docs state independently).

## Consequences

- t-2490's own AC are met by verdict, not by build: skill audit = t-2278's 34-skill classification stands on its own axis (runtime shape), and the **station/wrapper tiering is owned by [skill-tier mapping](../../research/2026-08-23-skill-tier-mapping.md)** (single owner of the W/A/A?/C table) (41 skills, measured 2026-08-23: W 8 · A 7 · A? 11 · C 15; no reclassification of t-2278's verdicts; the two axes are orthogonal); station contract = D3 + D4; t-2278 verdict = D1; ADR = this; follow-ups = below.
- `/brana:build` and `/brana:close` stay monoliths and stay the supervised entry. The cost accepted: they remain non-droppable into `Workflow` graphs — latent, not paid today (no loop or workflow invokes build headless; `epic-drain` is supervised-only), becoming real when ADR-062 unattended mode graduates (follow-up 2 is the tripwire). The benefit kept: enforcement lives in one place. (Tension, not contradiction: the-brana.md §Cycle → Decided has `/brana:close` *thinning to a session-band valve* — that is the direction; "stays a monolith" is the state this ADR leaves it in.)
- Skill authors get a rule they didn't have: new/adapted units are two-tier (D3), and the floor (D4) says when a phase earns extraction. `disable-model-invocation` is load-bearing for *reach* (t-2832 shipped); property (b) needs t-3041's lint.
- The loops-library keeps ownership of runtime grains (dead-letter, ASSIMILATE write-on-exit, RESTART state) — cross-referenced, not absorbed here (its own out-of-scope list, t-2826).
- Risk retained: churn on daily drivers if D6's pilots are skipped and generalization happens from vocabulary rather than a live adapter (the skills-as-loops load-bearing lesson: test hypotheses against a behavior's *shape*).
